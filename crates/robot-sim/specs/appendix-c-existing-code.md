**Superseded-history note:** The old Appendix C paragraph described `Twist`, `Wrench` and `SpatialInertia` as the current spatial API, and repeated an earlier source-inspection claim that the RNE core followed the same algorithm as the reference simulator. These are historical statements about the pre-Step-3 representation and prior source comparison, not a claim of measured numerical parity; the current oracle and regression tests do not compare outputs against the reference simulator.

**Audit note (2026-10-31):** the implementation was read in full against the step files and against `docs/example-system-specs/`, and the result is recorded in [Appendix D](appendix-d-mathematical-challenges.md). Two statements in the paragraph below need qualifying in light of it. First, the spatial algebra and the ABA/RNE recursions were independently re-derived and **agree term for term** with Featherstone, including the `a_0 = -g` gravity trick — this is a stronger statement than "covered by existing tests", though it remains a derivation and a code reading, not measured parity with the reference simulator. Second, the "existing closed-form, round-trip and energy tests" cited below do not reach the contact, collision, joint-limit or constraint paths in the archival battery; Appendix D M-20 records that gap, and eleven of Appendix D's twenty-four entries lie in exactly that uncovered region. Appendix D also names two **defects** outside `robot-sim` that this crate depends on: a non-unit joint axis makes the motion subspace disagree with the pose map (M-02), and `InertiaTensor::is_physically_plausible` accepts an indefinite tensor (M-03) — the latter being the function this appendix cites below as the existing validation idiom.

Current state: `robot_sim::spatial` and the ABA/RNE algorithm paths in `robot_sim::articulated` use plain fixed-size `f64` arrays and explicit formulas. Boundary adapters convert `robot-model` values, and the public `ArticulatedBody` API remains intact. The core is covered by existing closed-form, round-trip and energy tests, plus adapter and dense-solver regression tests; this is code-level oracle/test evidence, not measured the reference simulator parity. `Free` joints (Section 3 item 1) are implemented and validated. Since 0.1.5-draft the default path is `robot_sim::world`: CRBA / `M(q)` and its factorisation in `composite`, the unified contact, limit and equality solver in `solver`/`newton`, GJK/EPA and convex-hull collision in `collision`, and `implicitfast`/RK4 in `options`/`world`; `articulated` is kept as the oracle. Remaining gaps are `Ball` joints (Section 3 item 1, deferred per Appendix B row S-04), full `implicit`, the elliptic cone and constraint islands, a mid-phase BVH and named tiers. `robot_sim::pendulum` and `robot_sim::contact::ContactBody` remain the small, independently-qualified single-body benchmarks (`SPECS.md` Appendix B.4 item 2).
