**Superseded-history note:** The old Appendix C paragraph described `Twist`, `Wrench` and `SpatialInertia` as the current spatial API, and repeated an earlier source-inspection claim that the RNE core followed the same algorithm as MuJoCo. These are historical statements about the pre-Step-3 representation and prior source comparison, not a claim of measured numerical parity; the current oracle and regression tests do not compare outputs against MuJoCo.

Current state: `robot_sim::spatial` and the ABA/RNE algorithm paths in `robot_sim::articulated` use plain fixed-size `f64` arrays and explicit formulas. Boundary adapters convert `robot-model` values, and the public `ArticulatedBody` API remains intact. The core is covered by existing closed-form, round-trip and energy tests, plus adapter and dense-solver regression tests; this is code-level oracle/test evidence, not measured MuJoCo parity. `Free` joints (Section 3 item 1) are implemented and validated. Remaining gaps include `Ball` joints (Section 3 item 1, deferred per Appendix B row S-04), a constraint/contact solver (none is implemented; ground contact is a per-sphere penalty force only), collision beyond the current sphere-contact subset and single-point-mass benchmark (Section 6), and integrators beyond plain semi-implicit Euler (Section 4 items 3-4). CRBA / M(q) is not implemented. `robot_sim::pendulum` and `robot_sim::contact::ContactBody` remain the small, independently-qualified single-body benchmarks (`SPECS.md` Appendix B.4 item 2).
