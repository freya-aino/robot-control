# 0007 — checkpoints are a manifest plus per-state chunks, and load is all-or-nothing

- Status: accepted
- Date: 2026-10-27
- Touches: SPECS.md §9.2 (checkpoint/resume), SPECS.md §7.4 (frozen normalizer statistics), SPECS.md §13 (source revision), `PLAN.md` Phase 3 (checkpoint, parameter groups); `crates/robot-learn/src/checkpoint.rs` (new), `crates/robot-learn/src/ppo.rs` (crate-visible agent fields, group tables and masked update), `crates/robot-learn/src/gaussian_policy.rs` (`from_parts`), `crates/robot-learn/src/backprop.rs` (`Gradients::zero_frozen`), `crates/robot-learn/src/optimizer.rs` (`AdamState` moment accessors, `from_parts`, `step_masked`), `crates/robot-nn/src/mlp.rs` (`ParamGroup`, `ParamGroupError`, `Mlp::param_count`, `Mlp::frozen_mask`), `crates/robot-types/src/obs.rs` (`Normalizer` state accessors and `from_state`), `crates/robot-artifacts/src/chunk.rs` (`rows`, `cols`, `dtype`, `schema_digest`, `values` accessors)

## Context

SPECS.md §9.2 requires PPO to support checkpoint and resume, and PLAN.md Phase 3 requires the observation normalizer to be saved with the weights and named parameter groups with a frozen flag. A resumed run must match an uninterrupted one bit for bit, so every piece of state that affects the next update has to be saved: both networks, the policy log-std vector, both Adam moment sets and step counts, the normalizer's exact accumulators and count, the training configuration, the parameter-group tables, the generation counter and the RNG position. A checkpoint is a file-based artifact that another process must be able to read, so a truncated or edited file must be rejected rather than partially loaded. SPECS.md §13 also calls for a source revision; the checkpoint records it as manifest metadata when supplied, or records `unknown` when the save caller has no revision to provide.

## Decision

1. **Layout.** A checkpoint is a directory. Each state piece is one file, `<name>.chunk`, encoded by `robot_artifacts::chunk::Chunk`. A file `manifest.toml` is written last. It is the commit point: a directory without a manifest is not a checkpoint.
2. **Chunks.** The chunks are `policy` (layer weights then biases, per layer), `policy-log-std`, `value`, `policy-adam` (first moment then second moment), `value-adam`, `normalizer` (mean, `m2`, clip, epsilon), `config` (the six PPO scalars and two Adam configs), `counters`, `rng` and `param-groups`.
3. **Exact numeric encoding.** Every `f64` is stored as a `DType::F64` value, so the bits are preserved. The normalizer stores `m2`, the sum of squared deviations, rather than `variance`, because `variance * count` does not round-trip bit-exactly. Integers (`counters`, RNG words) are stored as `DType::U8` with eight little-endian bytes per `u64`, and each byte is checked to be an integer in 0..=255 on load.
4. **Counters.** The `counters` chunk holds, in order: generation, policy Adam step, value Adam step, normalizer count, epoch count and the normalizer frozen flag. Generation remains in this chunk rather than being duplicated in the manifest: it is mutable training state alongside the optimizer and normalizer counters, and a single canonical value avoids manifest/chunk disagreement. The loader rejects a frozen flag other than 0 or 1.
5. **Parameter-group table (`param-groups`).** A `DType::U8` chunk holding two lists, policy then value. Each list is a count, then per group: the name length, the name bytes, the range start, the range end and the frozen flag (0 or 1). Every number is an 8-byte little-endian `u64`. The loader rejects truncated data, trailing bytes, non-byte values, a non-UTF-8 name and a frozen flag other than 0 or 1. Each list is then checked against its network by `Mlp::frozen_mask`, which rejects an empty name, a duplicate name, an empty or reversed range, a range past `Mlp::param_count`, and overlapping ranges. A table that fails any check produces no agent.
6. **Freeze semantics.** A frozen group is enforced in the update path, not only in the table. `Gradients::zero_frozen` zeroes frozen gradient entries, and `AdamState::step_masked` skips the parameter, the first moment and the second moment for frozen entries. Momentum from earlier steps therefore cannot move a frozen weight, and the frozen weights are bit-identical after an update. The step counter still advances, which is a deliberate bias-correction choice and is not a weight change. Both masks reject a length mismatch with an error and change nothing. Parameters outside every group stay trainable.
   - **Policy flat space.** The `policy` table indexes the whole policy: the mean network's flat parameters (each layer's weights, then its biases) followed by the `log_std` entries, one per action dimension. `GaussianPolicy::param_count` and `GaussianPolicy::frozen_mask` define this space, and `frozen_mask_for_count` in `robot-nn` is the shared validator. `PpoAgent::update` splits the mask at `mean_net.param_count()`: the first part masks the mean network through Adam, and the tail masks `log_std` through `GaussianPolicy::apply_log_std_gradient`, which skips frozen entries bit for bit and rejects a length mismatch.
   - **Value flat space.** The `value` table indexes the value network alone, in the same flat order.
   - **Validation points.** A table is validated when it is set, when a checkpoint is saved (so an invalid table never writes a loadable-looking checkpoint), and when it is loaded. The update path re-derives the masks from the validated tables; if a public network field was replaced with a different shape after the tables were set, the update panics with a message naming the offending table instead of silently applying a stale mask.
7. **Manifest.** The manifest is TOML with `schema = "robot-learn.checkpoint"`, `schema_version = 2`, `source_revision`, the root seed as a string (to keep a full `u64`), the observation width, the layer widths and activation names for both networks, and a `[chunks]` table mapping each chunk name to its `ContentId` (`sha256:<hex>`). Writers always emit `source_revision`; `save` defaults it to `unknown`, while `save_with_metadata` accepts a caller-supplied revision. The reader treats an absent source revision in an earlier manifest as `unknown` for compatibility, and rejects a present non-string or empty value. The key follows the `Environment::source_revision` spelling in `robot_artifacts::manifest`; `unknown` identifies missing provenance but does not claim the full execution environment required by SPECS.md §13. The loader requires the chunk table to name exactly the expected set: a missing or extra name is rejected.
8. **Digests at two levels.** The manifest's `ContentId` is the SHA-256 of the chunk file bytes, verified before decoding. Each chunk also carries a schema digest, `digest_parts(["robot-learn.checkpoint.v2", name, dtype, layout])`, which `Chunk::decode` checks. A chunk therefore cannot be swapped under another name, and a change of dtype or layout is detected.
9. **Load is all-or-nothing.** `load_with_metadata` reads and verifies every chunk into locals, and returns the recorded `CheckpointMetadata { source_revision }` alongside the agent and RNG. `load` is a thin wrapper that drops the metadata. Before the agent is built, the loader rebuilds the networks, Adam states, normalizer, groups and RNG, and checks each one: layer shapes against the topology, policy input width against the observation width, value input width against the observation width, value output width equal to one, policy log-std length against policy output width, Adam moment lengths against the network, normalizer lengths against the observation width, the frozen flag as a 0/1 value, group tables against their networks, and the RNG seed against the manifest seed. `PpoAgent` is constructed only after every step has passed. Any error returns no agent, and no existing object is mutated.
10. **Save refuses to overwrite.** `save` fails if `manifest.toml` already exists. The chunks are written before the manifest, so an overwrite would expose a window in which the old manifest names new chunk bytes. Each checkpoint goes to a fresh directory.
11. **Atomic writes.** Each file is written with `robot_artifacts::store::write_atomic`, which writes to a temporary file, syncs and renames. The chunks are written before the manifest, so a crash mid-save leaves a directory with no manifest, which the loader rejects.
12. **Extensibility.** A future schema adds a chunk by adding an entry to `CHUNKS`, a matching entry in `payloads()`, read and validation logic in `load`, and bumps to `SCHEMA_VERSION` and `SCHEMA_TAG` so the chunk schema digest changes. The reader of version 2 rejects a version-1 manifest, because v1 has no `param-groups` chunk and the chunk table check would reject it anyway. The v1 to v2 change is a schema change, not a silent upgrade. Version-1 checkpoints must be re-saved.
13. **Limits.** Chunk decoding uses `ChunkLimits::default()`, and manifest parsing uses `TomlLimits::default()`. Width and length arithmetic is checked, so a hostile manifest produces an error and not an overflow.

## Consequences

- Checkpoints are portable across processes and machines: the format is little-endian, the floats are IEEE bit patterns, and the chunk bytes are deterministic for a given agent state.
- Any change to a chunk's content, layout or dtype is a schema change. The digest in each chunk and the version in the manifest make that detectable.
- Existing v1 checkpoints do not load under v2. There are no v1 checkpoints in the repository to migrate.
- The format stores the full Adam state, so a checkpoint is about 2× the parameter count in `f64` per optimizer. This is acceptable at the scale of the reference tasks; it is not designed for large networks.
- The `policy-log-std` chunk is separate from `policy` because `log_std` is not part of `Mlp`. A later change that folds it into the network must bump the schema.

## Verification

The checkpoint tests in `robot-learn` cover: resumed training equal to an uninterrupted run, compared bit for bit over both networks, log-std, both Adam moment sets and step counts, the normalizer, the RNG and the generation counter; a separate process that loads the directory and reproduces the same fingerprint; a round trip of the value parameter-group table; rejection at save time of an out-of-bounds table, with no manifest written; a corrupted `param-groups` chunk rejected on load; rejection of an unsupported schema version, a missing chunk file, a manifest digest attached to the wrong chunk, a corrupted chunk byte, a truncated manifest, a policy shape that disagrees with its weights, a policy or value input width that disagrees with the observation width, and a value output that is not one. The group decoder is tested directly on crafted bytes: a well-formed table decodes; a truncated table, an oversized length prefix or count, trailing bytes, a non-byte value (including NaN and a fraction), a non-UTF-8 name and a frozen flag other than 0 or 1 are each rejected with a specific message. A load-time overlap, rewritten with a matching manifest digest so that only the group check can reject it, is rejected with a message naming the policy table. The separate-process test re-runs the same test binary with `--exact` on a helper test, which does nothing unless the parent sets its environment variables.

The parameter-group tests cover: `Mlp::frozen_mask` marking exactly the frozen flat indices; rejection of an empty name, a duplicate name, an empty range, an out-of-bounds range and an overlap, each with its specific error; the optimizer keeping a frozen weight and a frozen bias bit-identical, including their first and second moments, after momentum has built up over five unmasked steps (the frozen entries carry nonzero gradients in the masked step, so only the mask can keep them still); mask-length mismatches in `step_masked` and `zero_frozen` rejected without changing the state; a PPO update with a frozen policy group and a fully frozen value network, where the frozen weights stay bit-identical after three rollout-and-update cycles while unfrozen parameters change; a PPO fine-tune after two training updates, with the hidden weights and `log_std` frozen, where those stay bit-identical through three more updates while the hidden biases and output weights change; a frozen `log_std` alone, which stays bit-identical while the mean network still changes; and invalid group sets leaving the agent's group tables unchanged.

## What this does not change

- Existing `PpoAgent` behaviour is unchanged when no groups are set: with empty tables the update path zeroes nothing and masks nothing. The only visibility change is that the agent's optimizer, config, generation and group fields are `pub(crate)`, so `checkpoint.rs` can construct the agent without a public constructor that bypasses validation.
- The normalizer's update rule and the RNG stream are unchanged. `Normalizer::from_state` and `AdamState::from_parts` rebuild checkpoint state; `Rng::snapshot` and `Rng::restore` already existed and the codec reuses them.
- No new dependencies are added. The checkpoint code uses `robot-artifacts` and `robot-types`, both already dependencies of `robot-learn`.
